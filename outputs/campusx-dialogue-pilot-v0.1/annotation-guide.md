# CampusX 多轮任务试标注规范 v0.1

日期：2026-09-17。状态：供人工试标注的研究草案；不是已完成的论文方法或正式金标准。

## 1. 数据与实验边界

复用 `../01a0a836-a9fe-7033-a17e-219829debdf2/campusx-products-100.json`。原文件不改写；快照 SHA-256 记录于 `examples.gold.json`。100 件全为合成商品，其中 90 件在售。本文的“符合条件”仅指目录描述可支持，不表示真实商品或真实世界性能已核验。商品 ID 是身份，重名不能合并。

标注侧可以读取 products 与 annotations；被评方法默认只能读取 products 的同一公开字段集合和已发生的对话。annotations、gold 状态、gold 商品集合、用户私有需求卡不得放入助手提示词、索引或工具结果。若另设共享结构化商品索引实验，应对全部方法提供同一份索引，并明确这是额外信息条件。

`examples.public.json` 仅作输入来源；回放器每轮只发送截至当前的用户消息，不一次发送未来消息。`examples.gold.json` 供标注与评估使用；`user-cards.private.json` 仅供用户模拟器或人工扮演者使用。分文件是权限边界的约定，本轮没有实现隔离运行器。

## 2. 需求状态与更新

每个任务从空状态开始，跨轮保留未被明确改变的条件。`state.slots` 保存完整快照；公共槽位为 `itemType`、`categoryId`、`price`、`locationZone`、`condition`，再加任务用到的 `attributes.属性名`。未出现的属性槽位等同于 unmentioned。

| slot.status | 含义 | 检索行为 |
| --- | --- | --- |
| unmentioned | 用户从未说明该字段 | 不加条件；不是已知“不在意” |
| constrained | 有活跃硬约束或软偏好 | 根据 clauses 执行 |
| unrestricted | 明确说不限、都可以 | 不筛选；保留此次表态和来源 |
| withdrawn | 明确撤销旧条件，未给替代条件 | 不筛选；不是恢复更早的旧条件 |

明确排除由活跃 `not_in` 子句表示，不能折叠为“不限”。同一槽位允许多个子句，例如价格下限与上限，或要求覆盖两个知识范围；它们按 AND 组合。`in` 内部是 OR。没有明确表达时不得把预算、地点、分类、颜色补成硬约束。

每个 clause 含 `id, op, value, strength, sourceTurn, supersedes`。`strength` 为 hard 或 soft；“必须”“只要”“不要”通常是硬约束，“优先”“更想，但其他也行”是软偏好。无法确定时记录歧义及允许澄清，不自行猜测。

每轮 `events` 是更新日志，含 `eventId, action, field, targetConstraintIds, clause, evidence`。action 包括 add、replace、withdraw、unrestrict；replace/withdraw 必须指向同一字段仍活跃的旧 clause ID。`evidence` 的 quote 必须出自本轮用户原话，start/end 使用 JavaScript UTF-16 索引，右侧不含末尾。派生状态不是助手自己的承诺；助手提议“预算提到 40 元”不产生需求更新，用户接受后才更新。

槽位的 `lastEventId` 标记最近一次更新；未更新的来源不能伪装为当前轮。撤销只删除所指条件；若同字段还有别的条件则仍为 constrained。明确不限清空该字段全部活跃条件。改变物品类型时，保留或清除哪些旧约束须由原话明确支持；本批 R03 专门明说保留预算和区域。没有这种依据的切换留待澄清，不能套用统一“全保留”或“全清空”。

## 3. 商品判断的三值语义

先按 on_sale 筛选，再对所有硬约束求值。每个条件为 true、false、unknown：

- 所有硬约束 true → `eligibleProductIds`，这是完整集合，不截到 5 件。
- 至少一个硬约束 false → 确定不符合，即使另有 unknown 也不放入待核验集合。
- 没有 false，至少一个 unknown → `undeterminedProductIds`，不能宣称已满足全部条件。

null、缺失属性键、原标注成色“未说明”是未知线索，但 annotations 不是完整事实库，必须先核对商品标题和正文。如果正文已明确说明，需补充带来源的评估映射并升级标注版本，不能因缺键盖过正文事实；例如SYN-P025的颜色未入属性表，正文仍明确是银色。本批影响匹配的缺键已核对正文，读取时视为 unknown；不修改原目录。数值 0 是已知价格，不是缺失。否定条件也遵循三值逻辑：轴体未知不能证明“不是青轴”。不适用属性不能凭缺失键断言为 true；后续如需区分 unknown 与不适用，须单独标注，不能偷偷更换本版含义。

未知用户需求可通过追问用户澄清；未知商品事实不能通过让用户猜测补齐。目录没有卖家核实工具，本版只允许说明待核验或询问用户是否愿意放宽自身条件，不伪造核实结果。

空集合细分：

- `nonempty`：有可确认商品。
- `undetermined_only`：没有可确认商品，但有待核验候选。回答应说明信息不足，不能断言目录中不存在。
- `conclusive_empty`：没有可确认或待核验候选。可以说固定目录中无满足项，不能自行放宽条件。

## 4. 本批运算符与归一化

| op | 精确定义 |
| --- | --- |
| eq | 归一化后的标量完全相等 |
| in / not_in | 已知标量属于 / 不属于给定集合；unknown 始终返回 unknown |
| lte / gte | 数值 ≤ / ≥，用于价格；不能直接比较“512GB固态硬盘”等字符串 |
| contains_all | 内容范围的概念集合包含所有指定概念，不做任意字符串子串匹配 |

本版仅对 `attributes.内容范围` 定义有限词表：高等数学、线性代数、概率统计、英语词汇、英语阅读、英语写作、政治基础概念、数据结构。目录里的“高等数学、线性代数与概率统计”分解为前三项。词表公开给所有方法，但逐商品标注只供评估。未列出的表达需人工复核后升级词表版本。

物品类型使用原 annotations.itemType 的精确取值。不能把“耳机”等同于整个 digital 分类，也不能把“台灯”隐含限制成 dorm：SYN-P039 属于 digital，仍是台灯。本批未要求知识推断式归一化。比如“全新未拆封”的盒面标注不等于实际开机测试正常；“基础版”只是合成版本标签，不对应 ISBN。

软偏好不缩小 eligible 集合。本批每轮最多一项软偏好：无 soft 时每件合格商品 relevance=1；有 soft 时，明确满足得 2，未满足或未知得 1，并另记 unknown。此分值仅是本批排序标注约定。以后多个偏好需先确定权重与比较规则，不能随意相加。

## 5. 动作和完整示例

`acceptableActions` 标注动作类别，不规定唯一自然语言答案。动作可以包括 search_and_recommend、ask_user、explain_no_confirmed_match、explain_no_match、propose_relaxation。放宽提议不是执行放宽。

动作类别命中不等于合理澄清；还须核对所问字段、已有答案、能否影响当前决策。I01问静音或区域都合理，反复问已明确的预算不因属于ask_user而得到相同评价。交互输出采用一个主动作、final标志与questionFields；具体终止规则记录在私有卡的outputProtocol。

`recommendedProductIds` 表示作为满足条件而推荐的商品；待核验和排除说明用独立的 `undeterminedProductIds`、`excludedProductIds`。不能把正文中所有ID都当作推荐；也不能通过漏填recommendedProductIds隐藏正文的实质推荐。评估者核对正文与结构化字段一致性，错误分类记回答问题。非终局回复中的明确推荐仍接受当轮可见约束检查。

回放示例每轮均包含原话、更新日志、完整状态、完整可确认集合、待核验集合、动作范围及一条 `referenceAssistantText`。参考话术是编写的示例，不是任何模型的实测输出。实际系统最多返回 5 件；集合大于 5 时允许不同合法子集，排序另评。回放主测只使用固定用户序列，参考助手话术不输入模型，避免它直接提示正确状态；如测指代，应另设对所有方法一致的上下文，不能引用各组不同候选的“第二个”。

R01—R06 是固定回放，I01 是有隐藏约束的交互任务，I02 是无需追问的对照需求卡。I01 的三轮是其中一条允许的示范路径，不能拿它的第二、三轮按固定脚本响应所有策略；实际回复须由 private 卡按所问字段产生。I02 可以第一轮结束，保留它是为了检验过度澄清。

## 6. 人工试标注流程与发布门槛

先复核这 8 个示例，再扩到 40 个。建议由作者与另一位标注者独立阅读商品正文和用户原话，分别标注状态、更新目标、结果集合、动作是否合理；第二位标注者不先看这份模型草案。若暂时只有作者，记录为作者单人复核，不称独立双人标注。

逐项记录分歧，再讨论裁决；保存初始版本和理由。至少核查每个 eligible 商品、每个 undetermined 商品，以及预算边界、非在售、同名不同属性等近似干扰项。程序对全目录枚举只能检查规则执行一致性，不能证明语言解释正确。

`human-review-template.md` 提供记录表。正式使用前需补真实标注者代号、日期、裁决与快照版本。任何未解决语义分歧的条目保留 draft 或剔除，不能为了凑足 40 个自动通过。修订快照或词表后重新计算 gold；已接触过并据此调试的任务全部保持开发用途。
