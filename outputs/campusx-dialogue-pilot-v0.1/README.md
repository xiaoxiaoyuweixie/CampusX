# CampusX 多轮需求任务试点 v0.1

日期：2026-09-17。用于论文《面向校园二手交易的多轮需求澄清与约束保持检索智能体研究》的离线试标注。

本包已完成 **40任务构建方案、8个标注草案（30轮）、2张隐藏需求卡及离线一致性校验**。没有构建完40个任务，没有实施论文智能体，没有跑模型效果实验，没有锁定测试集；全部示例尚待独立人工复核。

## 建议阅读顺序

1. [任务方案与对照实验设计](pilot-plan-and-experiments.md)：40个任务配额、两条评测轨道、基线、指标、切分与文献依据。
2. [8个完整示例，人工可读版](examples-readable.md)：每轮原话、更新关系、完整需求状态、合格/待核验集合和参考话术。
3. [标注规范](annotation-guide.md)：未提及/不限/排除/撤销、硬软约束、来源轮、三值匹配与人工流程。
4. [人工复核记录模板](human-review-template.md)：供真实标注者填写，目前为空白。

## 机器文件与访问边界

| 文件 | 用途 | 能否输入被评助手 |
| --- | --- | --- |
| [examples.public.json](examples.public.json) | 回放用户消息；交互任务仅首句 | 按轮揭示，不能一次输入未来消息 |
| [examples.gold.json](examples.gold.json) | 完整状态与正确商品集合草案 | 否，只供评估/标注 |
| [user-cards.private.json](user-cards.private.json) | 完整隐藏目标、问答规则、允许放宽、终止规则 | 否，只供模拟用户与评估 |
| [validation-report.json](validation-report.json) | 重算结果、未知事实审计、软偏好分级 | 否，只供核验 |
| [validate-pilot.cjs](validate-pilot.cjs) | 固定快照下的离线校验器 | 不是检索智能体或实验运行器 |

私有卡中的outputProtocol只是拟实施的交互契约；本轮没有实现用户模拟器、运行隔离或模型评分系统。正文中的明确推荐应与recommendedProductIds一致；对“已排除”“待核验”商品的解释性提及不等同推荐。

annotations不是穷尽的事实库。比如部分属性没列键但正文已说明；相关未知判断应先核查正文。本批已对实际影响结果的未知项逐项检查，并保留审计依据；这属于程序校验和模型内容复核，不是独立人工标注。

## 本轮验证

在项目根目录运行：

```bash
node --check outputs/campusx-dialogue-pilot-v0.1/validate-pilot.cjs
node outputs/campusx-dialogue-pilot-v0.1/validate-pilot.cjs
```

校验器重建逐轮状态、枚举全部100件商品，并与预先写入的示例集合比对；检查证据位置、来源轮、更新目标、公开输入字段边界和私有卡目标。当前8任务30轮与2张卡均通过。R05最终为确定无解；R06最终仅有待核验商品SYN-P048，不能把两者混为一种空结果。

报告中的软偏好等级只用于试标注，未计算模型检索指标。自然语言含义、澄清是否合理及真实世界有效性，不能由程序一致性检查证明。校验器专用于本版固定快照；更换快照或新增涉及未知属性的任务时，需要更新语义审计，不能仅改哈希绕过检查。

本轮仅在此目录新增研究材料，保留原有未提交改动，没有修改业务源码。业务端构建与云函数部署不属于本轮验证范围。

下一步先人工复核这8个草案，记录分歧、修订规范，再构建剩余32个开发任务；根据论文层次、期限与调用预算确定正式实验规模。
