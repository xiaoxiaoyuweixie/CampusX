## 1. 文档说明

### 1.1 需求背景与目标

CampusX 用户围绕商品进行沟通时，需要自主决定是否提供微信号和手机号，也需要在聊天中发送文字、拍照或发送相册图片。本次需求将联系方式的填写、开放与关闭集中到个人页面，并统一聊天中的联系权限和消息发送行为。

本期目标：

- 用户可以分别填写、修改和关闭微信、电话联系方式，不强制提供任何一项。
- 聊天联系入口依据对方当前开放状态和已保存的非空号码判断，不将「开关开启」等同于「联系方式可用」。
- 对方被禁用或关联商品下架、售出时，按明确规则限制聊天、复制微信号和拨号。
- 文字通过键盘「发送」提交，照片或相册图片选定后直接发送，并保留草稿和失败内容。

本 PRD 定义本次新增与调整的业务行为；项目架构、公共接口契约及状态枚举仍遵循根目录 `spec.md`。本次不修改已有业务代码。

### 1.2 适用人员

| 对象 | 使用重点 |
| --- | --- |
| 产品 | 功能范围、状态转换、权限边界、反馈文案 |
| 设计 | 入口位置、四种联系方式页面状态、底部填写弹窗、聊天输入区和反馈状态 |
| 研发 | 保存与开关规则、实时权限判断、联系方式获取、消息发送和草稿隔离 |
| 测试 | 各业务模块末尾的验收标准及异常、并发和边界场景 |

本文中「本人」是当前登录用户，「对方」是当前商品会话中的另一位用户。「微信」指用户自行填写的微信号，不指微信登录身份或平台授权信息。

## 2. 功能范围与全局规则

### 2.1 本期功能范围

| 模块 | 本期内容 | 使用身份 |
| --- | --- | --- |
| 「我的」页面 | 在「我的收藏」下新增「联系方式」入口 | 已登录用户 |
| 联系方式页面 | 手动设置、修改微信号和手机号；独立开关；空值保存；保存反馈 | 资料所属用户本人 |
| 聊天联系入口 | 独立判断微信和电话可用性；脱敏展示微信号；复制完整微信号；原生拨号 | 当前会话参与者 |
| 联系权限 | 对方禁用、商品下架或售出、对方关闭或修改号码后的即时生效规则 | 当前会话参与者 |
| 聊天消息 | 键盘发送文字；拍照或相册选图后直接发送；草稿保留；失败重试 | 满足发送权限的会话参与者 |

登录与账号身份沿用现有机制。只能修改本人的联系方式，不能通过更换用户标识修改其他人的资料；不新增管理员编辑联系方式的能力。

### 2.2 本期不包含

- 独立 iOS / Android App、Web 管理端页面改版。
- 交换申请、对方同意、双向解锁、付费解锁或要求本人先开放联系方式。
- 手机短信验证、微信号真实性校验、手机号格式校验及第三方账号绑定。
- 语音、视频、文件发送、自定义表情、客服和举报功能。
- 新增独立发送按钮、图片发送前的自定义二次确认页。
- 订单、支付、交易担保或已复制联系方式的远程撤回。
- 为本需求强制引入新的 IM 系统、长连接架构或跨设备草稿同步。

### 2.3 联系方式可用性与隐私规则

**基础判断。** 某项聊天联系入口可用，必须同时满足：当前登录与会话访问权限有效、对方账号未被禁用、关联商品在售、对方开启了该项开关、该项已保存的号码非空。微信与电话分别判断，不能用一个总开关替代。

当对方仅开放微信时，则只有微信入口可以使用；不要求本人也填写或开放微信。电话同理。

| 判断对象 | 规则 |
| --- | --- |
| 号码 | 已保存的内容为空或尚未填写时，不可用于聊天联系；不因开关开启而变为可用 |
| 开关 | 控制对应联系方式是否向其他用户开放，不表示已验证号码真实性 |
| 本人管理页 | 本人可查看、修改自己保留的号码；关闭不删除号码 |
| 对方聊天页 | 只能按当前权限使用该项联系方式，不得通过缓存或直接请求绕过关闭状态 |
| 微信展示 | 只展示脱敏内容；完整微信号仅用于获得授权后的复制动作 |
| 电话获取 | 仅在允许拨号时获取并交给原生拨号能力，不额外增加完整号码展示弹窗 |
| 历史已复制内容 | 对方关闭后阻止新的复制、拨号操作；不承诺撤回已经写入系统剪贴板的内容 |

**历史聊天定义。** 「已有聊天记录」指当前用户、对方及该关联商品的同一会话中，至少存在一条已成功发送的消息，文字或图片均可。仅创建会话、输入草稿、消息发送中或发送失败，均不构成已有聊天记录。其他商品、其他对话人的记录不能用于放行。

**权限优先级。** 登录及账号权限限制优先于商品状态，再判断具体联系方式。以下表格以本人登录与账号权限正常为前提；本人被禁用时不得借用对方状态正常绕过现有账号限制。

| 对方状态 | 关联商品 | 成功消息历史 | 发起新聊天 | 原会话继续发送文字 / 图片 | 查看已有消息 | 复制微信 / 拨号 |
| --- | --- | --- | --- | --- | --- | --- |
| 正常 | 在售 | 无 | 允许 | 允许 | 无记录可展示 | 分别按对方号码和开关判断 |
| 正常 | 在售 | 有 | 复用原会话 | 允许 | 允许 | 分别按对方号码和开关判断 |
| 正常 | 已下架 / 已售出 | 无 | 禁止 | 禁止，包括已创建但无成功消息的空会话 | 无记录可展示 | 禁止 |
| 正常 | 已下架 / 已售出 | 有 | 禁止新增，进入原会话继续沟通 | 允许 | 允许 | 禁止 |
| 被禁用 | 任意 | 无 | 禁止 | 禁止 | 无记录可展示 | 禁止 |
| 被禁用 | 任意 | 有 | 禁止 | 禁止，历史记录只读 | 允许只读 | 禁止 |

沿用项目现有枚举：用户 `enabled` / `disabled`，商品 `on_sale` / `off_shelf` / `sold`；不得将本文中文展示文案写成新的数据库状态值。

**生效与数据边界。** 当联系方式、开关或账号、商品状态更新成功后，则权限以服务端最新状态为准。已打开的聊天页也应同步更新入口，不要求用户退出后重新进入才能失效。每次复制、拨号、发送消息前仍须由服务端校验当前权限，不能只依赖页面按钮状态。网络异常或无法确认授权时，不使用缓存完整号码继续执行联系操作。

沿用现有云函数数据访问边界和 `{ code, message, data }` 业务响应，不让小程序直接读写云数据库。本 PRD 规定生效结果，不指定新云函数名称、数据库字段名或额外的实时通信技术。

### 2.4 原生能力与系统界面约定

| 操作 | 约定 |
| --- | --- |
| 页面及填写弹窗 | 沿用当前小程序原型的样式、颜色和已有组件，复用顶部控件、小程序控件 |
| 图片来源选择 | 使用微信原生操作菜单：拍照、从相册选择、取消 |
| 拍照及选图 | 使用原生拍照或相册界面，不新增自定义确认页；原生界面自带的确认步骤保留 |
| 拨号 | 使用微信原生拨号能力，确认界面跟随系统，不自绘拨号确认弹窗 |
| 文字发送 | 使用软键盘上的「发送」动作，不新增常驻独立发送按钮 |
| 系统差异 | iOS、Android 的原生界面可不同，业务权限和保存、发送结果必须一致 |
| 用户取消原生操作 | 正常返回聊天，不发送图片或拨号，不展示失败提示，不清空文字草稿 |

成功提示默认展示 2 秒，失败提示默认展示 3 秒；原生系统提示按系统行为执行。发生异常时，不向用户暴露技术堆栈、数据库字段或内部异常信息。

## 3. 联系方式管理

### 3.1 「我的」页面新增联系方式入口

原型参考：[我的 / 联系方式入口预览](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=199-1385)。

1. 在「我的」页面的「我的收藏」入口下方新增「联系方式」。图标、行高、右侧箭头及分隔方式沿用同组入口组件。
2. 当已登录用户点击该入口时，则进入本人的「联系方式」页面，读取已保存号码及两项开关状态。
3. 当点击页面返回按钮时，则返回来源页面；不因进入、返回页面自动修改号码或开关。
4. 当登录状态失效时，则沿用现有登录处理，不展示或修改其他账号的联系方式。

### 3.2 联系方式页面与独立开关状态

原型参考：[全部关闭](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=204-1520)、[全部开启](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=204-1568)、[仅微信开启](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=202-2608)、[仅手机开启](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=202-2625)。

页面标题为「联系方式」，保留说明文案：

> 微信和手机信息用于其他用户直接联系你时使用，若不希望提供可关闭，关闭后所有功能均不会向其他用户展示该信息。

内容顺序为「微信」「手机」。每项包含独立开关；开启后展开号码信息行和「修改号码」入口，关闭后收起信息行。

| 微信开关 | 手机开关 | 微信模块 | 手机模块 |
| --- | --- | --- | --- |
| 关闭 | 关闭 | 仅标题和开关 | 仅标题和开关 |
| 开启 | 关闭 | 展示微信号信息行和「修改号码」 | 仅标题和开关 |
| 关闭 | 开启 | 仅标题和开关 | 展示手机号信息行和「修改号码」 |
| 开启 | 开启 | 展示微信号信息行和「修改号码」 | 展示手机号信息行和「修改号码」 |

当首次使用、号码尚未填写时，两项初始为关闭，不默认向外开放。开启空号码项目时，只展开空信息行及「修改号码」，不自动弹出填写弹窗，也不让聊天联系入口可用。两项编辑入口统一命名为「修改号码」，即使尚未填写也不改称「新增」或「绑定」。

**开关操作流程：**

1. 用户点击某项开关，发起该项状态更新；另一项号码及状态不变。
2. 当开启成功时，则展开信息行；若有保留的号码，则展示本人已保存内容。开启操作本身不打开编辑弹窗。
3. 当关闭成功时，则收起信息行并停止对外开放该项内容，已保存号码继续保留。
4. 当开关更新失败时，则恢复操作前已持久化的状态及展开情况，提示「操作失败，请重试」。
5. 同一项开关请求处理中防止重复提交，避免连续点击产生状态倒置。最终以成功保存的状态为准。

| 数据项 | 填写或更新规则 | 关联关系 |
| --- | --- | --- |
| 微信号 | 用户手动填写，允许为空，不做格式及真实性校验 | 是否对外可用由保存值和微信开关共同决定 |
| 手机号 | 用户手动填写，允许为空，不做格式校验或短信验证 | 是否对外可用由保存值和手机开关共同决定 |
| 微信开关 | 用户可单独开启、关闭；保存微信号成功时开启 | 不影响手机开关 |
| 手机开关 | 用户可单独开启、关闭；保存手机号成功时开启 | 不影响微信开关 |

这里的「不校验」指不添加号码格式、长度、号段或真实有效性规则，不免除身份和操作权限检查。不得将号码解析为数字后保存，也不得擅自改变其大小写、前导字符或内容。

### 3.3 设置、修改微信号

原型参考：[设置微信号弹窗状态](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=204-1645)。

**前置条件：** 用户处于本人的联系方式页面，微信信息行已展开。

1. 当点击微信模块「修改号码」时，则打开底部弹窗，标题为「设置微信号」。弹窗包含微信号输入框、右上角关闭按钮和底部「确定」按钮。
2. 当已有保存值时，则输入框回填完整微信号；尚未填写时，输入框为空。管理本人信息时不使用聊天页的脱敏值回填。
3. 用户可以填写、修改或清空内容，不做格式校验。
4. 当点击「确定」时，则提交当前输入；空内容同样允许提交，不提示必填错误。
5. 当保存成功时，则使用新值覆盖旧值、开启微信开关、关闭弹窗，信息行展示保存结果并提示「已保存」。
6. 当保存的是空内容时，则清除原微信号，微信开关仍按保存成功规则开启，但任何聊天中的微信入口均不可用。
7. 当点击关闭按钮或通过返回操作退出弹窗时，则丢弃本次未保存编辑，保留原号码及原开关状态。

编辑草稿与已保存值分离。输入过程中不直接改变对外展示；只有保存成功后才生效。

### 3.4 设置、修改手机号

原型参考：[设置手机号弹窗状态](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=220-458)。

1. 当点击手机模块「修改号码」时，则打开标题为「设置手机号」的底部弹窗，回填本人已保存的完整手机号。
2. 用户手动填写或清空内容。不获取平台绑定手机号，不发送短信，不校验号段、格式或号码真实性。
3. 当点击「确定」且保存成功时，则覆盖已保存手机号、开启手机开关、关闭弹窗并提示「已保存」。
4. 当保存空内容时，则覆盖并清除旧手机号；手机开关开启，但聊天中的电话入口不可用。
5. 当取消编辑时，则不更新号码和开关；关闭手机开关时仍保留已保存号码。

手机号不做格式校验不代表系统能成功拨打任意输入。实际拨号由原生能力处理；不得把「拨号失败」反向当作保存手机号的校验规则。

### 3.5 保存反馈与异常处理

成功提示原型参考：[已保存提示条](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=220-1361)。失败状态按当前项目已有输入、按钮和提示样式补齐，不新增业务步骤。

当提交正在处理时，确定按钮进入处理中状态并防止重复提交。一次保存必须同时完成该项号码更新和该项开关开启；不得只修改了开关却提示整个保存成功。

当服务端明确返回保存失败时，弹窗保持打开，输入不丢失，原号码和原开关仍有效；用户可以修改后再次提交或取消。网络失败不得显示「已保存」，也不得仅在本地伪造保存结果。

当提交后响应丢失、无法确认是否已保存时，先保留本次输入并提示失败，恢复通信后重新读取实际状态；不能承诺服务端一定未保存，也不能用本地回滚覆盖已经成功保存的数据。开关操作同样适用。后续重试仍以当前明确提交内容为准。

| 场景 | 文案 / 反馈 | 数据和界面结果 |
| --- | --- | --- |
| 保存成功，包括保存空内容 | 已保存 | 关闭弹窗，对应开关开启，另一项不变 |
| 服务端明确保存失败 | 保存失败，请重试 | 弹窗和本次输入保留，原保存值及开关不变 |
| 服务端明确开关更新失败 | 操作失败，请重试 | 开关及展开状态恢复为操作前结果 |
| 提交后结果未知 | 使用对应保存或操作失败文案 | 不伪造成功；保留编辑，重新读取实际保存状态后校准 |
| 取消编辑 | 不展示成功或失败提示 | 未保存编辑丢弃，原数据不变 |
| 页面数据加载失败 | 沿用现有加载失败及重试反馈 | 不把读取失败显示成真实的空号码或已关闭状态，不提交未知状态 |

## 4. 聊天中的联系方式

### 4.1 微信与电话入口的可用状态

原型参考：[不可用状态](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=190-1527)、[可用状态](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=190-1575)。除全部可用、全部不可用外，须补齐仅微信可用和仅电话可用的组合。

1. 当进入聊天页时，则读取当前会话的商品、对方账号和联系方式可用状态。
2. 当某项满足第 2.3 节条件时，则对应按钮使用可操作样式；不满足时置灰，不执行复制或拨号。
3. 当点击不可用入口或操作过程中权限已失效时，则按第 4.4 节提示原因，不打开可操作的联系弹窗。
4. 联系方式由对方单方面开放即可使用；不创建交换申请，不等待双方确认，不检查本人是否也开放该项号码。

| 对方对应开关 | 对方对应已保存号码 | 全局账号 / 商品权限 | 该项联系入口 |
| --- | --- | --- | --- |
| 关闭 | 空或非空 | 允许 | 不可用 |
| 开启 | 空 | 允许 | 不可用 |
| 开启 | 非空 | 允许 | 可用 |
| 任意 | 任意 | 不允许 | 不可用 |

用户仍可在权限允许时只通过文字或图片聊天，不填写联系方式不会阻断正常在售商品的聊天。

### 4.2 微信号脱敏展示与完整号码复制

原型参考：[交换微信弹窗](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=191-1305)、[已复制提示](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=190-1626)。

1. 用户点击可用的微信入口，系统重新确认权限并打开「交换微信」弹窗。
2. 弹窗展示交易提醒、字段标题「对方微信号」和脱敏微信号，底部操作为「取消」「复制微信号」。
3. 当点击「取消」时，则关闭弹窗，不复制号码，不创建交换记录或授权流程。
4. 当点击「复制微信号」时，则重新检查对方账号、关联商品、微信开关及当前保存值；通过后将最新完整微信号写入系统剪贴板。
5. 只有系统复制成功后才展示「已复制」。失败时展示「复制失败，请重试」，不伪造成功结果。

保留原型交易提醒文案：

> 请优先选择当面验货交易，不要提前转账、支付定金或押金；私下交易转账付款造成的纠纷、损失及不法侵害本平台概不负责。

该文案作为当前产品展示内容，不构成对其法律效力的认定。

**脱敏规则：**

| 输入情况 | 展示规则 | 示例 |
| --- | --- | --- |
| 非空且至少 4 个字符 | 前 2 位 + 固定 4 个星号 + 最后 1 位 | `abcdef` 展示为 `ab****f`；`abcd` 展示为 `ab****d` |
| 非空且少于 4 个字符 | 仅展示固定 4 个星号 | `a`、`ab`、`abc` 均展示为 `****` |
| 空值 / 尚未填写 | 入口不可用，不生成可复制的号码展示 | 不把 `****` 当作真实号码或可用占位值 |

复制内容必须为完整原始保存值，保留大小写等原内容，不复制星号、不拼接提示文案。当号码在弹窗打开后发生变化时，须按最新有效值更新展示并复制，不使用过期号码。

### 4.3 调用原生拨号

原型参考：[原生拨号说明](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=190-1730)。原型注释中的「交换成功后」不作为前置条件。

1. 用户点击可用的电话入口。
2. 系统重新校验权限并获取对方当前完整手机号，通过后调用微信原生拨号能力。
3. 用户在原生系统界面继续拨号或取消，不增加自绘的「交换电话」弹窗，不要求先复制或交换微信。
4. 当取消时，则返回聊天，保持文字草稿，不提示拨号失败。
5. 当原生能力失败时，则保留当前聊天和草稿，按系统或项目现有通用错误反馈处理，允许用户再次操作；不得显示已拨通或已联系成功。

系统弹出拨号界面不等同于电话接通。本期不记录或推断通话成功、接通状态及通话时长。

### 4.4 对方及关联状态变化后的处理

**对方修改或关闭联系方式：** 当对方保存新号码时，现有聊天后续操作使用新值；当对方关闭某项开关或将该项保存为空时，该项入口立即不可用，另一项独立判断。若交换微信弹窗已经打开，则不得继续复制过期或已关闭的号码，应同步使复制动作不可用并提示原因。

**商品下架或售出：** 当关联商品不再在售时，不允许发起新聊天。有至少一条成功消息的原会话可以继续发送文字及图片，但微信和电话入口均不可用。只有会话记录而无成功消息时，不可借已有会话标识发送第一条消息。

**对方被禁用：** 无论商品状态和联系方式是否开启，均禁止发起聊天、发送文字、发送图片、复制微信号和拨号。已有历史消息保留且只读；不因为只读而清空历史。输入及图片发送操作不可提交。

**操作期间状态变化：** 若用户打开弹窗、进入相册或编辑草稿后权限发生变化，则实际复制、拨号、发送时仍应用最新规则。已打开的原生系统界面或此前已复制的号码无法承诺远程撤回，但状态失效后不得再次向该用户提供完整号码。

| 场景 | 提示文案 | 阻止的动作 |
| --- | --- | --- |
| 对方微信关闭或微信号为空 | 对方暂未开放微信联系方式 | 打开可复制弹窗及复制 |
| 对方电话关闭或手机号为空 | 对方暂未开放电话联系方式 | 调用拨号 |
| 下架商品尝试发起新聊天或空会话首次发送 | 商品已下架，无法发起聊天 | 创建新聊天及首次发送 |
| 售出商品尝试发起新聊天或空会话首次发送 | 商品已售出，无法发起聊天 | 创建新聊天及首次发送 |
| 下架或售出商品尝试联系 | 商品已下架或已售出，无法获取联系方式 | 复制微信号及拨号 |
| 对方被禁用 | 当前无法与该用户联系 | 新聊天、文字和图片发送、复制及拨号 |
| 系统复制操作失败 | 复制失败，请重试 | 不展示复制成功 |

多个条件同时失效时，优先提示账号禁用，再提示商品状态，最后提示具体联系方式未开放。业务拒绝须使用对应原因，不统一显示为网络失败。

## 5. 聊天消息发送

### 5.1 聊天输入区域调整

输入区沿用正式聊天区域原型，不使用「过程草稿-可忽略」中的其他工具栏。

- 保留微信、电话入口，其权限按第 4 章执行。
- 保留文字输入框与图片按钮；输入占位文案为「看对眼就聊天，沟通更多细节～」。
- 不新增独立发送按钮、表情、官方客服、举报等截图过程稿中的控件。
- 当不能发送消息时，输入区进入不可提交状态；已有草稿和历史消息不因权限变化被误清空。
- 当不能复制或拨号但允许继续原会话聊天时，只限制对应联系入口，不连带禁用文字和图片发送。

### 5.2 通过键盘发送文字

1. 用户点击输入框，系统键盘提供「发送」动作。
2. 当点击键盘「发送」时，先判断内容和当前会话权限。
3. 当内容为空、仅空白或超过长度限制时，不发送，展示对应提示并保留输入。
4. 当内容和权限允许时，进入发送中状态，防止同一次发送重复提交。
5. 当服务端确认成功时，消息进入成功状态，清理本次已发送内容对应的输入草稿。若用户已开始新的输入，不得误删新内容。
6. 当发送失败时，保留失败内容和重试入口，提示「消息发送失败，请重试」；不得仅清空输入而让内容丢失。

| 项目 | 本次默认规则 |
| --- | --- |
| 发送方式 | 键盘「发送」 |
| 单条长度 | 最多 1,000 字符；前后端采用一致计数口径，不按字节数判断 |
| 空内容 | 空字符串及纯空白文字不可发送 |
| 普通内容 | 不额外改写消息，不用联系方式字段的不校验规则放行空消息 |
| 提交防重 | 同一条消息发送中不可重复提交 |
| 成功判定 | 服务端确认成功，不以本地出现气泡或上传开始作为成功 |
| 失败处理 | 内容保留，支持手动重试；不静默无限重试 |
| 重试一致性 | 网络响应丢失后重试不得造成同一条消息重复入库或重复展示 |

本文的 1,000 字符限制用于用户之间的商品聊天，不覆盖或修改项目中 AI 助手的输入限制。

### 5.3 拍照、相册选图与直接发送

原型参考：[原生拍照与选图说明](https://www.figma.com/design/ypmVzm832Ho7LpKxfyzsnO?node-id=190-1729)。

1. 当用户点击图片按钮时，则打开原生操作菜单，提供「拍照」「从相册选择」「取消」。
2. 选择「拍照」进入原生相机；选择「从相册选择」进入原生选图界面。
3. 用户完成原生拍照或选图确认后，返回聊天。系统检查文件限制和当前会话发送权限，通过的图片直接发送，不增加自定义发送确认弹窗或二次预览步骤。
4. 多张图片按照用户选择顺序组织，每张生成一条消息；上传完成先后不应导致展示顺序混乱。
5. 当其中一张失败时，其他符合条件的图片继续发送。失败图片保留失败状态及手动重试入口，已成功图片不随整批重试重复发送。
6. 当取消菜单、取消拍照或取消选图时，不生成消息，不提示失败，文字草稿保持不变。

| 项目 | 本次默认规则 |
| --- | --- |
| 单次选图数量 | 最多 9 张，不静默发送超出数量的图片 |
| 单张大小 | 实际提交上传的文件不得超过 10 MB |
| 文件格式 | JPG / JPEG、PNG、WebP 静态图片 |
| 不支持内容 | 视频、动态 GIF 等不在本期范围 |
| 发送确认 | 沿用原生拍照或选图确认；返回后直接发送，不新增应用内二次确认 |
| 多图顺序 | 以用户选择顺序排列，一图一条消息 |
| 局部失败 | 失败图片单独标记和重试，不阻断其他图片 |
| 草稿关系 | 发送图片不清空未发送的文字草稿 |

当图片过大或格式不支持时，该图片不上传为聊天消息，展示对应提示；其他符合条件的图片仍可处理。当原生相机、相册权限被拒绝或能力不可用时，按原生系统或项目既有错误反馈处理，返回后保留文字草稿，不伪造发送结果。

当用户在相册期间对方被禁用，或商品失效且当前会话尚无成功消息时，则返回后的图片发送被拒绝；不能因为选图时曾经可用而绕过最新权限。若商品失效前已有成功消息，则仍允许在原会话继续发送图片。

### 5.4 输入草稿与发送异常处理

**草稿保留：** 文字输入随编辑保留在本地，按当前账号和会话分别存储。离开聊天页、进入相册或相机再返回、重新进入同一会话时，恢复未发送的文字。切换会话或账号时，不串用其他会话或账号的草稿；不要求跨设备同步。

**清理时机：** 用户主动清空输入时更新为空草稿；文字消息成功发送后清理对应已发送内容。发送失败、取消原生操作、仅成功发送图片、联系方式开关变化或会话暂时只读，不自动清空文字草稿。

**失败重试：** 失败消息保留可识别的失败状态和内容，用户可以手动重试。重试前重新校验权限与内容限制。每条消息必须能防止重复提交，包含「服务端已成功但客户端未收到成功响应」场景；不能通过重试向对方重复发送同一条消息。防重以同一次消息提交及其重试为范围，不禁止用户主动发送两条内容相同的独立消息。

| 状态 | 表现 | 允许操作 |
| --- | --- | --- |
| 草稿 | 仅在本地输入区，未发送 | 编辑、清空、在权限允许时发送 |
| 发送中 | 对应消息显示处理中状态 | 不重复提交该条消息 |
| 发送成功 | 作为正常消息展示 | 计入本会话成功消息历史 |
| 发送失败 | 保留内容并标记失败 | 权限允许时手动重试 |
| 只读 | 历史消息仍可阅读，发送不可用 | 查看历史，不提交文字或图片 |

上述为交互状态，不要求新增或重命名项目已有数据库枚举。

| 场景 | 提示文案 / 反馈 | 内容处理 |
| --- | --- | --- |
| 空白文字消息 | 请输入消息内容 | 不发送，输入保留 |
| 文字超限 | 单条消息最多输入1000字 | 不发送，输入保留供修改 |
| 文字发送失败 | 消息发送失败，请重试 | 保留失败内容，可手动重试 |
| 图片超限 | 单张图片不能超过10MB | 该图片不作为消息发送，不清空文字草稿 |
| 格式不支持 | 暂不支持该图片格式 | 该图片不发送，其他符合条件的图片不受影响 |
| 图片发送失败 | 图片发送失败，请重试 | 保留失败项，单独重试 |
| 用户取消拍照或选图 | 不展示失败提示 | 不生成新消息，保留文字草稿 |
| 对方被禁用或商品限制发送 | 使用第 4.4 节对应业务文案 | 不发送，不清空已有草稿或历史 |

### 5.5 验收标准

| 编号 | 条件与操作 | 预期结果 |
| --- | --- | --- |
| MESSAGE-01 | 当打开正式聊天输入区时 | 有文字输入框、图片按钮和微信、电话入口；无新增独立发送、表情、客服或举报控件 |
| MESSAGE-02 | 当输入有效文字并点击键盘「发送」时 | 发送一条消息，服务端成功后正常展示并清理对应草稿 |
| MESSAGE-03 | 当输入为空或仅空格、换行等空白并发送时 | 不生成消息，提示「请输入消息内容」 |
| MESSAGE-04 | 当分别提交 1,000 和 1,001 个字符时 | 前者在其他条件满足时可发送，后者被阻止并提示上限；输入可继续编辑 |
| MESSAGE-05 | 当同一消息发送中连续触发发送时 | 不重复提交；成功后只出现一条消息 |
| MESSAGE-06 | 当文字发送失败或成功响应丢失后重试时 | 内容不丢失；可手动重试；不会产生重复消息 |
| MESSAGE-07 | 当点击图片按钮时 | 原生菜单提供拍照、从相册选择、取消，分别进入对应原生界面 |
| MESSAGE-08 | 当完成拍照或选图确认时 | 检查文件和权限后直接发送，不出现新增的应用内发送确认页 |
| MESSAGE-09 | 当选择多张符合限制的图片时 | 单次不超过 9 张，一图一条，按选择顺序展示 |
| MESSAGE-10 | 当包含大于 10 MB 或不支持格式的图片时 | 对应图片不发送并给出相应提示；其他符合条件的图片可继续发送 |
| MESSAGE-11 | 当一批图片中某张上传或发送失败时 | 仅该张标记失败，可单独重试；其他成功项不重复发送 |
| MESSAGE-12 | 当取消图片菜单、拍照或选图时 | 不生成消息、不显示失败提示，保留原文字草稿 |
| MESSAGE-13 | 当输入文字后进入相册、相机或离开再回到同一聊天时 | 恢复当前账号在该会话的草稿 |
| MESSAGE-14 | 当切换会话或切换账号时 | 不显示其他会话或账号的草稿 |
| MESSAGE-15 | 当发送图片成功、发送文字失败或会话变成只读时 | 未成功发送的文字草稿不被自动清空 |
| MESSAGE-16 | 当商品下架或售出且会话已有至少一条成功消息时 | 可继续原会话文字及图片发送，但不能复制微信或拨号 |
| MESSAGE-17 | 当商品下架或售出且只有空会话、草稿或失败消息时 | 无法发送第一条文字或图片，不能将本地失败气泡视为成功历史 |
| MESSAGE-18 | 当进入相册后对方被禁用，再返回尝试发送时 | 发送被拒绝并提示业务原因，历史只读，草稿与失败内容不丢失 |
| MESSAGE-19 | 当相机或相册权限被拒绝、网络失败时 | 展示适用的系统或业务反馈，不伪造成功，不清空草稿，可重新操作 |
| MESSAGE-20 | 当在 iOS 和 Android 微信中执行上述流程时 | 原生界面可不同，但保存、可用性、发送限制、取消和历史只读规则一致 |
