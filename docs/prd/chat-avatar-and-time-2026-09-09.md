## 1. 任务卡

### 1.1 目标与范围

用户在商品聊天中能够辨认消息发送者，并通过居中时间分隔了解消息发生时间。

| 项目 | 说明 |
| --- | --- |
| 适用页面 | 微信小程序商品聊天详情 `pages/chat/index` |
| 使用身份 | 当前商品会话的参与者，沿用既有登录与会话读取权限 |
| 本期内容 | 双方每条文字、图片消息的头像；聊天消息之间的分组时间；已加载历史消息及本地发送中、失败消息的相应展示 |
| 非目标 | 消息列表、系统通知、AI 助手和管理端的展示改版；新增头像点击行为；调整输入区、联系方式或发送权限；更换聊天架构 |
| 就绪状态 | 业务范围及决定性规则已确认，当前无待确认业务项 |
| 实施状态 | 本地实现及自动验证已完成，见第 3.4 节；尚未完成开发者工具界面、真机验收或发布 |

### 2.2 全局约束及 AI 自主边界

| 规则 ID | 要求 | 依据 |
| --- | --- | --- |
| REQ-CHAT-META-001 | 本期只扩展任务卡所列消息区域。原有文字与图片发送、草稿隔离、重试去重、分页、商品与账号权限继续生效。头像和时间出现不等于消息发送成功，不改变未读计数或成功消息历史判定 | 用户范围确认；`CONTACT-CHAT-API-001`；既有聊天 PRD |

开发 AI 可沿用现有模式决定局部函数划分、展示字段名、样式复用方式和测试组织。时间分隔属于页面展示元素，不得伪装成一条业务消息入库，不得影响消息 ID、数量、分页总数或重试关联。

需要新增交互、改变时间口径或头像语义、调整公共 action、重排既有业务消息、修改读取权限、引入依赖或迁移历史数据时，先暂停相关变更并确认；可以继续其他已确认部分。公共接口与云函数边界遵循 `spec.md`，不允许小程序直接读写数据库。

### 2.3 时间字段与历史数据边界

| 现有字段 | 已核实语义与使用边界 |
| --- | --- |
| `createdTimestamp` | 毫秒时间戳；本地首次提交时生成，重试沿用。服务端保留现有校验，将有效请求时间限制为不晚于实际入库时间。本期展示和分组以该记录值为准 |
| `createdAt` | 服务端实际写入时间，保存在数据库中；不能将它直接替代正常消息的首次发送记录时间 |
| `time` | 当前云端生成的短文案：当天仅时分，其他日期仅月日。不能直接满足本期完整格式，也不能据此反推丢失的年份、时区或分钟 |

当前工作区与 HEAD 的发送逻辑都会写入两种原始时间，未检查线上数据，也没有证据表明正常历史记录缺少 `createdTimestamp`。本期历史展示覆盖既有接口能够读取的消息，不据此开展全量数据清理。

对于缺失或无效的原始时间，不得使用当前时间、相邻消息时间或短 `time` 文案伪造时间，消息内容仍应可读且页面不能报错。如实际发现需要恢复缺字段旧数据，可核实已有 `createdAt`，但必须同时检查服务端按 `createdTimestamp` 查询和分页的结果；不能只补响应字段就宣称解决旧数据分页。涉及响应契约、查询规则或补数据的兼容方案，按第 2.2 节确认后执行。

## 4. 消息头像展示

### 4.1 原型与流程

[图片占位：Chat Page（264:2042）消息区域，标明左侧对方头像、右侧本人头像及其与消息气泡的位置关系。]

用户进入会话后，系统加载消息和双方资料，再根据消息发送方向将头像放在对应一侧。发送文字或图片时，本地消息也显示本人头像；收到新消息或加载历史后使用相同布局。头像读取或加载失败只影响头像，不影响消息内容和原有操作。

### 4.2 规则

| 规则 ID | 前提与触发 | 系统结果 | 确认依据 |
| --- | --- | --- | --- |
| REQ-CHAT-AVATAR-001 | 渲染任意双方文字、图片消息，包括连续消息和已加载历史 | 每条消息均显示圆形头像；对方头像在左侧气泡外，本人头像在右侧气泡外。同一人连续发送也不隐藏或合并头像。原型头像直径 32px（375px 画框），小程序按对应比例适配；与气泡顶部对齐，长文字和图片不能挤压头像或产生横向溢出 | 原型；用户确认第 1、2 项 |
| REQ-CHAT-AVATAR-002 | 首次进入、返回会话，或成功取得更新后的用户/会话资料 | 使用当前账号资料中的本人头像、会话响应中的对方头像；同一发送者的新旧消息使用一致的当前头像，不保存发送时头像副本。对方用户记录不存在时沿用现有会话快照回退。本人返回页面读取当前 `userInfo`，对方按既有消息加载和轮询响应更新，成功取得新值后同步更新已加载消息 | 用户确认第 2 项；已有资料与会话适配 |
| REQ-CHAT-AVATAR-003 | 头像为空或图片加载失败 | 复用消息列表私信的缺省呈现：蓝色渐变圆形背景、白色昵称首字。昵称缺失沿用会话的「校园用户」兜底，不能渲染 `undefined`。账号资料中已有可加载的系统默认头像时仍按该头像值显示；本期不新增头像素材、不使用登录页装饰图替代。头像地址更新后可加载新头像，不因旧地址失败而永久占位 | 用户明确复用当前消息页默认头像；消息列表源码 |
| REQ-CHAT-AVATAR-004 | 点击头像，或消息处于发送中、失败、只读状态 | 点击头像无操作，不进入资料页、不预览头像、不触发消息图片预览。发送中和失败消息继续显示本人头像及原有状态/重试入口；有权读取的只读历史继续显示头像 | 用户确认第 2 项；REQ-CHAT-META-001 |

默认头像复用依据是 `pages/message/index.wxml` 的私信 `.avatar` 与 `index.wxss` 中对应样式，而不是系统通知的「通」头像。可按聊天消息尺寸适配，不要求修改消息列表现有尺寸或补改它的图片错误处理。

### 4.3 验收标准

| 用例 ID | 关联规则 | 前置数据 / 操作 | 预期结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| AC-CHAT-AVATAR-001 | REQ-CHAT-AVATAR-001 | A、B 各发送文字及图片，同一账号连续发送；切换账号查看会话并加载历史 | 每条均有头像，左右随当前登录身份切换；长文字、横图、竖图及失败文案下头像不被压缩，内容不溢出 | 页面测试＋开发者工具／真机 |

## 5. 分组发送时间展示

### 5.1 展示结构与流程

[图片占位：Chat Page（264:2042）中居中的 `09-05 11:31`、`09-08 14:31` 时间分隔及其下方消息。时间内容为原型样例，不是固定文案。]

时间占用消息列表中的独立一行，以浅灰文字居中显示在对应消息上方，不放入左右气泡。加载、发送、接收或恢复待重试消息时，先按现有逻辑合并、去重并排序，再依据下列规则计算时间分隔。页面没有任何消息时，不额外展示日期或当前时间。

### 5.2 规则

| 规则 ID | 前提与触发 | 系统结果 | 确认依据 |
| --- | --- | --- | --- |
| REQ-CHAT-TIME-001 | 展示任意有效的消息记录时间 | 统一转换为北京时间（UTC+8），按 `MM-DD HH:mm` 显示；月、日、时、分均补齐两位，24 小时制，不显示秒。当天、往日、跨年历史采用同一格式，均不加年份，不替换为「今天」「昨天」「刚刚」 | 用户确认第 4 项及三个示例 |
| REQ-CHAT-TIME-002 | 计算当前已加载并合并后的消息列表 | 第一条有有效时间的消息显示时间；后续消息与紧邻上一条消息相差 ≥300,000 毫秒，或两者的北京时间自然日不同，即在该条消息上方显示该条消息自身的时间。发送者和消息类型变化本身不触发新时间。同一条同时满足多个条件只显示一次 | 用户确认第 3 项；原型分组结构 |
| REQ-CHAT-TIME-003 | 本地首次发起发送、发送失败、重试、恢复待发送队列或收到成功确认 | 沿用消息首次发起发送时的记录时间，重试不改为重试时刻或成功时刻；成功后使用服务端返回的既有 `createdTimestamp`，保留原有服务端校验。本地发送中和失败项参与本人当前列表的时间分组，但仍保留状态提示，不作为对方已收消息或会话成功历史 | 用户确认第 5 项；既有时间字段及发送逻辑 |
| REQ-CHAT-TIME-004 | 首次加载、加载更早消息、轮询新消息或云端消息替换同一条本地消息 | 每次按合并去重后的当前列表重新计算。新增历史后重新判定原列表首条与其新增前一条之间是否需要时间，不能按分页各自保留多余分隔。时间行不进入消息去重、计数或持久化；遵守原有滚动触发条件，不因重算时间强制跳到聊天底部 | 用户确认历史消息范围与分组规则；REQ-CHAT-META-001 |

第 2.3 节异常时间防护同样适用：没有有效时间的消息不伪造时间条；紧邻前一条时间无效、无法判断间隔时，下一条有效消息显示自身时间以恢复阅读定位。不改写异常记录或推断其发送时间。

### 5.3 分组判定细节

- 「上一条」指当前列表中紧邻的上一条消息，包含文字、图片及本地待发送项；不是上一条时间分隔所代表的消息，也不是同一发送者上一条消息。
- 间隔按完整毫秒值判断，再将展示文字截取到分钟。例如实际间隔 4 分 59 秒，即使显示的分钟数相差 5，也不满足间隔条件。
- 自然日判断包含真实年份、月份和日期，均按北京时间计算；展示不含年份不影响跨年排序和跨日判断。
- 当前只加载最近一页时，该已加载列表首条显示时间；「首条」不指用户滚动后屏幕最上方偶然可见的消息。
