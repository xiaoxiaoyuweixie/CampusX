## QA-20260914-01：消息图标缺少红点

**复现步骤：** 两个可正常聊天的账号 A、B 建立会话；A 停留在首页等带底部导航的页面；B 向 A 成功发送新消息；A 查看底部“消息”图标。

**实际表现（用户反馈）：** 图标右上角没有红点。

**预期：** 账号存在未读消息时，在“消息”图标右上角显示红点。这里是红点，不是未读数字徽标。

**修复前代码证据与原因（`9d2aae8`）：**

- 小程序使用原生 TabBar，“消息”为第 4 项（索引 3）：[app.json](/Users/mac172/Desktop/opd/CampusX/miniprogram/app.json:50)。
- `miniprogram/` 中没有 `showTabBarRedDot`、`hideTabBarRedDot` 或 `setTabBarBadge` 调用；[App 初始化](/Users/mac172/Desktop/opd/CampusX/miniprogram/app.js:3) 也没有未读同步逻辑。
- [消息列表](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/message/index.js:11) 仅在 `onShow` 加载数据；[WXML](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/message/index.wxml:31) 只显示会话行内的未读数字。会话行内标记不会自动更新原生 TabBar。
- [api.unreadCount](/Users/mac172/Desktop/opd/CampusX/miniprogram/api/index.js:55) 只是未被调用的定义，目标 `message` 云函数不在当前仓库中，不能直接当作已实现的未读接口。

**隔离验证：** 使用现有内存云数据库 fixture，A 发送文字后，B 的会话未读数为 1；查询会话列表保持 1；B 获取最新消息页后变为 0。使用微信 API 替身执行消息页 `onShow`，注入 `unread=1` 的会话，页面保留该值，但 TabBar 红点调用次数为 0，`unreadCount` 调用次数为 0。说明在这些场景下服务端已有计数，前端未将其连接到导航图标。

**修复范围建议：** 接通当前账号的权威未读状态与原生 TabBar 红点，覆盖前台刷新、阅读后的同步及账号切换。消息列表当前仅获取前 50 个会话，不能不加说明地将这一页的汇总当作全部未读状态。

**建议复验与回归：**

| 场景 | 检查结果 |
| --- | --- |
| 在首页、分类、发布、我的页收到文字或图片 | 按约定刷新时机显示消息图标右上角红点 |
| 消息页保持打开时收到新消息 | 红点和会话未读状态能更新，不依赖重新进入页面 |
| 阅读一个会话后仍有其他会话未读 | 红点保留 |
| 全部会话已读 | 红点消失 |
| 多于 50 个会话，未读位于未加载部分 | 不漏报未读 |
| 后台期间收到消息，恢复前台 | 重新核实并显示正确状态 |
| 网络失败、退出登录、切换账号、旧请求迟到 | 不将失败误当全部已读，不串用其他账号的红点状态 |
| 重试发送与已读处理 | 未读数不重复增长，旧会话阅读与发送功能正常 |

以上场景的自动化验证和真机待验范围见本文末尾；本次实现的常规刷新间隔为请求结束后 5 秒。

## QA-20260914-02：交换微信弹窗未居中

**复现环境与步骤：** iPhone 16 Pro，键盘未打开。打开允许联系且对方已开启有效微信号的商品会话；点击“微信”入口；观察交换微信弹窗的位置。

**实际表现（用户截图已确认）：** 白色弹窗左右留白基本一致，水平方向已居中；上边缘紧贴导航栏下方的页面内容顶部，整个弹窗明显偏上，没有垂直居中。截图中底部聊天输入栏可见，系统键盘未显示，与用户说明一致。交易提醒、脱敏字段及两个按钮均可见，当前证据未显示内容裁切。

**证据带来的判断：** 这项视觉缺陷已由真实截图确认，不再只是待截图核实的反馈。键盘打开不是发生问题的必要条件，不能将“打开弹窗前收起键盘”当作唯一修复。截图不能证明页面内部 `keyboardHeight` 的数值或原生容器的实际计算样式，因此具体代码根因仍需运行时核查。

**预期：** 弹窗在页面可视区域水平、垂直居中；完整显示提醒、脱敏号码、取消和复制按钮。

**初次核查事实（修复前）：**

- [弹窗 WXML](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/chat/index.wxml:44) 已声明 `page-container position="center"`，因此不能把原因写成“忘记设置居中”。
- 本机微信开发者工具随附的 WXML 组件文档列出 `position` 支持 `top`、`bottom`、`right`、`center`。不能把 `center` 误判为非法值。在线官方页面未能成功读取，本次依据为工具内置文档。
- [弹窗样式](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/chat/index.wxss:40) 定义宽度、最大宽度及 `margin: auto`；实际弹出层定位依赖原生容器，单看这段样式不能证明真机位置正确。
- [打开弹窗](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/chat/index.js:271) 在权限预览成功后设置 `contactOpen`；[键盘处理](/Users/mac172/Desktop/opd/CampusX/miniprogram/pages/chat/index.js:89) 会更新页面底部留白。结合本次键盘关闭的证据，应优先核查弹出容器与内容的实际高度、纵向定位及样式生效情况，键盘开关保留为回归场景。
- 弹窗 `page-container` 与聊天根节点 `.page` 是兄弟节点，键盘高度绑定的底部内边距只作用于 `.page`。源码未显示该留白直接作用于弹窗，不能据此断言键盘把弹窗顶到了上方。
- 已查看仓库[交换微信设计图](/Users/mac172/Desktop/opd/CampusX/docs/design/2026-09-08-app-ui-v1/wechat-dialog.png)，并核对 [PRD 弹窗内容与复制规则](/Users/mac172/Desktop/opd/CampusX/docs/prd/contact-and-chat-2026-09-07.md:257)。几何居中的最终预期沿用本次用户反馈。

工具内置文档位置：`/Applications/wechatwebdevtools.app/Contents/Resources/package.nw/js/libs/vseditor/extensions/wxml-language-features/server/dist/node/htmlServerMain.js`，其中 `name:"page-container"` 对应的属性说明。

**本次定位：** 本机微信开发者工具随附的 `WAWebview.js` 中，`.weui-popup--center` 将弹出容器设为 `height:100%; left:0; top:0; width:100%`，没有把子元素垂直居中的布局。原 `.contact-dialog` 是普通块，`margin:auto` 只在水平方向分配空间，纵向仍从容器顶部开始。这一布局机制与用户截图吻合；`center` 属性合法，缺失的是容器内的子元素居中。尚未读取该 iPhone 体验版的运行时计算样式，因此本地运行时证据不能当作该设备已完成修复验收。

## 2026-09-14 修复交付

### 代码已修复

**消息红点：**

- 新增 `chatService.getUnreadState`，使用真实云端 `OPENID` 校验账号，从全部参与的 `active` 会话查询本人买家/卖家角色是否存在未读；返回 `{ code, message, data: { hasUnread } }`。查询存在性不受列表 50 条分页限制，不改动现有发送累加和读取清零规则。
- API 适配已接入该 action，删除未使用且指向不存在云函数的 `unreadCount`。原生 TabBar 索引 3 显示无数字红点；初版使用系统红点 API，随后按用户确认改为带红点的普通/选中图标，详见本文末尾位置调整记录。
- 新增全局未读控制器：首次登录、五个 Tab 显示、成功读取聊天消息后、App 恢复前台立即刷新；前台登录时每次请求结束后等 5 秒再次查询。慢请求期间不启动另一请求，重复触发合并为至多一次后续刷新；后台清除计时器并丢弃旧响应。
- 退出/换号立即清空旧账号缓存状态，并用账号与代次校验迟到结果。网络失败、业务错误、无效响应保留当前账号最后确认的红点；非 Tab 页绘制失败时回到 Tab 重绘。
- 消息页订阅全局刷新来更新会话列表，只在可见时订阅；请求合并，失败保留列表，隐藏/换号使旧响应失效。轮询不额外重复请求旧系统通知接口。
- 资料查询/更新回写增加账号代次保护，防止退出或换号后晚返回的资料重新写入旧登录身份。未增加账号管理或新的业务规则。

**交换微信弹窗：**

- 保留原生 `page-container position="center"`，显式让容器填满可视区域，以 flex 在水平和垂直方向居中；对话框宽高以父容器为上限，短屏允许内部滚动，没有机型专用顶部偏移。
- 外层空白区域透传点击给原生遮罩，内层对话框可交互，继续使用 `beforeleave` 和取消按钮原关闭方法。
- 键盘已打开时，打开弹窗前尝试收起键盘并恢复列表空间；输入内容和本地草稿不变。键盘关闭场景由布局本身保证居中。
- 交易提醒、脱敏规则、复制时重新鉴权、剪贴板失败重试、电话入口和原生返回机制保持原有实现。

稳定规则已同步至 `spec.md` 的 `CHAT-UNREAD-001` 与 `CHAT-CONTACT-DIALOG-001`。
