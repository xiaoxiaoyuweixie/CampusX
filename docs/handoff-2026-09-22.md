## 4. 在另一台电脑恢复开发

### 克隆与依赖

准备 Git、Node.js/npm、微信开发者工具，以及具备仓库/小程序/云环境访问权限的账号。`reportService/package.json` 要求 Node.js `>=20.9.0`；其云端运行时按既有部署文档使用 Nodejs20.19。新电脑安装依赖时应符合该最低版本，不复制旧电脑的 `node_modules`。

```bash
git clone https://github.com/xiaoxiaoyuweixie/CampusX.git
cd CampusX
git status --short
npm --prefix admin-web ci
npm --prefix cloudfunctions/reportService ci --include=optional
```

- 根目录及原生小程序没有 `package.json`，不要在根目录盲目执行 `npm install`。
- `admin-web` 和 `reportService` 有 `package-lock.json`，使用 `npm ci` 恢复锁定依赖。举报测试真实调用 Sharp 解码，必须安装 optional dependencies 及当前系统/CPU 对应二进制。
- 其余云函数各自有 `package.json`，本次检查没有对应 lock 文件；仅在确需本地调试某函数时进入该函数目录 `npm install`。部署继续使用云端安装依赖，不上传本机二进制，尤其是 `reportService` 的 Sharp。

### 导入原生微信项目

在微信开发者工具中导入 **CampusX 项目根目录**。根目录的 `project.config.json` 已指定 `miniprogramRoot: "miniprogram/"`、`cloudfunctionRoot: "cloudfunctions/"` 和小程序 AppID，不要另建空项目替代。

登录获授权的开发者微信，选择现有云环境 `cloud1-d6g5stkeb92288dee`，重新编译。克隆代码不会部署函数；若云端仍缺少 `getUnreadState`，按下文部署提示处理，不要把不支持 action 的错误当成没有未读消息。

### 管理端本地配置与运行

仅在需要管理端时，若 `admin-web/.env` 不存在，再从 `admin-web/.env.example` 复制生成。通过安全渠道恢复正确接口配置；已有文件先核对，不覆盖另一台电脑自己的配置。

```bash
npm --prefix admin-web run dev
```

浏览器打开终端显示的本地页面地址。修改 `.env` 后重启 Vite。不要将 `.env`、密钥、登录 token 或真实用户资料提交到 GitHub。

### 首次验证

在项目根目录运行：

```bash
node --test tests/*.test.js
find cloudfunctions -path '*/node_modules' -prune -o -name '*.js' -print -exec node --check {} \;
npm --prefix admin-web run build
```

自动化测试主要使用隔离数据库/微信 API 替身，不能代替云端权限、双账号联调或真机视觉验收。微信开发者工具重新编译后，按首页和聊天验收记录检查设备表现。构建通过也不代表真实管理端接口配置正确或已上线。
