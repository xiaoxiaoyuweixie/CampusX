# 联系方式与聊天功能部署、验收

实现依据：`docs/prd/contact-and-chat-2026-09-07.md`。本文件说明代码接入与部署要求，不改变 PRD 中已经确认的业务规则。

## 部署顺序

1. 在云开发控制台检查数据库权限：`users`、`chat_sessions`、`chat_messages` 仅服务端读写，客户端不得直接查询或修改。否则联系方式开关和会话权限可以被绕过。
2. 配置下述云存储规则。聊天图片不得沿用商品图片的公开读取权限。先核对现有规则，不要覆盖项目无关目录的权限配置。
3. 上传并部署 `user`、`product`、`chatService`，使用云端安装依赖。无需新增云函数或数据库集合。`chatService` 必须连同 `lib/`、`services/` 一起部署；建议超时设为 60 秒以允许检查、转存最大 10 MB 的图片。
4. 部署 `adminService`，构建并更新管理端静态资源，用于兼容图片消息查看；不是管理端页面改版。
5. 微信开发者工具重新编译小程序并进行真机测试。本地修改不会自动部署到线上。

## 数据兼容

- `users.contacts.wechat`、`users.contacts.phone` 分别为 `{ value: string, enabled: boolean }`。缺失字段视为空值、关闭，无需批量迁移旧用户。
- 用户资料、登录和商品详情接口不向其他用户返回完整联系方式；仅本人管理接口和通过当前权限验证的复制、拨号接口按需要返回。
- 保留原会话、消息和状态值。新增消息类型 `image`；文字仍为 `text`，成功状态仍为 `sent`。
- 旧会话是否允许在商品失效后继续发送，以实际存在的成功消息为依据，不以 `lastMessage` 占位或本地气泡为依据。
- 新客户端发送消息必须带稳定 `clientMessageId`，手动重试沿用原值。不同新消息使用不同值，即使内容相同。
- 旧客户端不带标识的文字请求仍可发送，由服务端生成独立标识；只有升级后的客户端能保证响应丢失后的跨请求重试去重。
- `createdTimestamp` 作为展示顺序，`createdAt` 作为服务端确认时间。多图按选择顺序逐张提交；失败项重试仍保留原排序时间。

## 云存储安全边界

- `chat-staging/`：客户端上传的临时文件，仅上传者可读取、写入。
- `chat-media/`：云函数检查文件头、大小及动画标识后生成的独立副本。客户端禁止直接读写，不能用替换原上传文件的方式改写已发送内容。
- 聊天参与者查看图片时，由云函数鉴权后签发临时链接；管理端沿用管理员鉴权。已取得的临时链接在到期前无法保证远程撤销，不应当作永久公开地址缓存。
- `getMessages` 不返回云文件 ID；历史图片可在双方账号状态变化后由具有会话读取权限的人继续查看。

若现有非聊天目录采用“所有人可读，仅创建者可写”，以下为合并示例（应在控制台确认当前规则语法与现有目录权限后使用）：

```json
{
  "read": "(/^chat-staging\\//.test(resource.path) == false && /^chat-media\\//.test(resource.path) == false) || (/^chat-staging\\//.test(resource.path) == true && auth != null && auth.openid != null && resource.openid == auth.openid)",
  "write": "/^chat-media\\//.test(resource.path) == false && auth != null && auth.openid != null && resource.openid == auth.openid"
}
```

此示例只覆盖聊天目录；同时部署举报功能时，使用[举报部署文档](report-feature-2026-09-12.md)中的合并条件，避免正式举报证据落入公开读取分支。正则使用独立前缀表达式，避免控制台不支持的分组语法。按[官方特殊方法语法](https://docs.cloudbase.net/rule/learn-rules)，每次 `.test(resource.path)` 都显式与 `true` 或 `false` 比较；本地 JavaScript 校验不能替代云端保存与双账号验证。

若控制台仅提供简易权限且不能按路径配置，请先确认私有聊天图片的独立存储方案，不要把 `chat-media/` 改为公开读取来绕过报错。本文未自动修改任何线上权限。

上传中断或事务失败可能留下未关联消息的临时文件。可按 `chat-staging/` 前缀设置清理策略；`chat-media/` 不能直接按时间整批删除，需先比对消息引用。客户端重试时可重新上传本地保留文件。

官方参考：[云存储安全规则](https://docs.cloudbase.net/storage/security-rules)、[数据库事务](https://docs.cloudbase.net/database/transaction)。

## 双账号真机验收

- 本人联系方式两项开关的四种组合，空值保存，关闭保留原号码；网络失败后重进读取实际值。
- 不开放本人号码，也可使用对方已开放的联系方式；默认请求只含脱敏微信号，不含完整电话。
- 一端打开微信弹窗，另一端修改、清空或关闭微信；前端通过现有 5 秒轮询更新，每次复制仍独立请求服务端，不能使用旧值。
- 在售空会话可发送；下架/售出空会话不可首次发送；已有成功消息的原会话可继续文字和图片，但不可获取联系方式。
- 对方禁用后历史只读；进入相册期间发生状态变化，返回后仍拒绝不允许的发送。
- 键盘发送 1000/1001 个 Unicode 码点、纯空白、前后带空格的文本。AI 助手限制保持不变。
- 连点发送、响应丢失后重试，数据库只生成一条消息；在上一条发送中输入新内容，不被旧请求成功回调清空。
- 拍照、相册取消不报错；选多图保持顺序；单张超过 10 MB、GIF/APNG/动态 WebP 被拒绝；某张失败不影响其他张，单张重试不重复已成功项。
- 离开会话再返回恢复草稿与待重试项；切换账号、会话不串草稿；图片成功不清空文字。
- iOS/Android 检查键盘高度、底部安全区、原生菜单/拨号取消、复制失败、图片缩略图及点击查看。
- 管理端正常展示旧文本消息和新图片消息。

自动化测试使用隔离的内存数据库及微信 API 替身，不访问线上用户数据。不能替代真实 CloudBase 权限、事务冲突和两台设备上的原生能力验收。
