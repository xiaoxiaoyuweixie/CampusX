# 后台用户详情部署与验收

## 本次范围

- 用户列表操作列新增「查看」，保留启用/禁用按钮。
- 详情只读展示昵称、账号、性别、个性签名、状态、更新时间、微信号、电话号码。
- 个性签名使用 `users.bio`；更新时间缺失时使用创建时间。
- 启用状态的超级管理员可查看完整联系方式，不受用户对外展示开关限制；详情同时标示开放状态，空值显示「未填写」。
- 列表仍不下发 `contacts`，小程序聊天权限和联系方式开关逻辑不变。
- 接口契约见 `spec.md` 的 `ADMIN-USER-DETAIL-001`。

## 部署顺序

1. 在微信开发者工具中上传并部署 `cloudfunctions/adminService`，包含其 `lib/` 和 `services/` 目录，按现有方式安装云端依赖。新增 action 为 `getUserDetail`，沿用已有 HTTP 入口和管理员鉴权。
2. 在 `admin-web` 目录运行 `npm run build`。
3. 将本次生成的 `admin-web/dist/` 内容更新到现有腾讯云管理端静态托管位置。
4. 刷新管理端网页。若仍显示旧列表，强制刷新浏览器后再验证。

只部署管理端网页、未更新 `adminService` 时，点击「查看」会收到「请求的操作暂不支持」。本次不需要新增集合、环境变量或修改数据库/存储访问权限，也不需要重新发布小程序。

本地开发服务器也调用配置的 `VITE_ADMIN_API_URL`；本地页面更新不能代替云函数部署。不要将管理员 token 或真实联系方式写入共享文档、测试样例或日志。

## 验收步骤

1. 使用启用状态的超级管理员登录，进入用户列表，确认每行同时有「查看」和原有启用/禁用按钮。
2. 点击「查看」，核对八项资料；顶部显示「用户详情」，侧栏仍选中「用户列表」。
3. 在小程序中设置本人微信和电话后关闭展示开关，刷新后台详情：完整号码仍可见，标注「未对外开放」。管理员查看不修改号码或开关。
4. 查看未填写联系方式的用户：显示「未填写」，不显示 `undefined`，不使用样例号码替代。
5. 使用详情的返回按钮回到用户列表；重新进入详情后点击顶部「刷新」，应重新查询当前用户而不是跳回列表。
6. 验证长号码、多行签名和带有 HTML 字符的资料：完整换行展示，不能执行脚本。
7. 用户不存在时显示中文错误，保留返回和重试入口；查询期间切换页面或退出登录后，迟到响应不得重新显示联系方式。
8. 管理员登录失效时重新进入登录页；未登录、被禁用或非超级管理员的直接接口请求均不得返回资料。

## 本地验证命令

在项目根目录运行：

```bash
node --test tests/admin-user-detail.test.js tests/admin-user-detail-view.test.js
find cloudfunctions -name '*.js' -print -exec node --check {} \;
```

在 `admin-web` 目录运行 `npm run build`。

自动化测试使用隔离数据库和模拟页面事件，不访问生产数据，不能代替部署后的真实账号联调。
